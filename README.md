# 安心药盒 · 场景 A Demo

面向能够独立生活、按既定方案长期使用多种药品的老人，演示「计划核对 → 当次任务 → 开盒 → 未确认声音提醒 → 本人确认或待核实 → 记录回看」。

## 运行

需要 Node.js 22 或更新版本，无需安装依赖。

```sh
node server.mjs
```

打开 http://127.0.0.1:4173 。Mac 可双击 `启动演示.command`。默认仅监听本机；关闭服务后链接不再可访问。

## 三分钟演示

1. 今日用药：在演示控制台开启提示音与语音，点击「模拟到点提醒」。
2. 点击「模拟打开药盒」。药格亮灯，状态变为「已开盒 · 未确认」。
3. 不做确认，8 秒后触发提醒，再过 8 秒触发第二次提醒；之后停止自动提示，仍保持未确认。
4. 点击「不确定是否已服用」：停止催促，显示待核实；只有用户核实并确认后才记为本人确认已服用。
5. 重复开盒、刷新页面，确认记录仍保留。在「用药记录」查看和导出事件。
6. 计划设置：选择「试试缺少时间的示例」，提取后时间留空，不能保存。换成完整示例，对照核对后勾选确认并生成任务。

## 智能能力与 Mock 范围

- 配置 `DEEPSEEK_API_KEY` 后使用 **DeepSeek 真实模型**，默认 `deepseek-flash`；没有密钥时使用本地规则演示。每行一条安排，格式为 `示例药品 A，08:00，每次 1 片`。同一药品不同时间需分行输入。规则模式不支持任意自然语言。
- 已实现可选模型接口。启动服务前通过环境变量设置 `AI_API_URL`（完整 chat-completions 兼容请求地址）、`AI_API_KEY` 和 `AI_MODEL`。密钥只在服务端使用。请求以 messages 输入，读取 choices[0].message.content 中的 JSON。已实测 DeepSeek：明确的“早上八点”转换为 08:00，仅有“每日两次”时具体时间留空。
- 接入模型时，点击提取会把输入文本发送到配置的服务商；使用虚构安排演示。日期仍由用户手动核对，模型不负责自动推断日期或时间。
- 硬件、药格灯光和开盒传感器均为页面模拟。到点事件使用按钮手动触发；未确认倒计时真实运行。没有后台推送、关页提醒或真实硬件控制。
- 声音使用 Web Audio 提示音及系统语音合成。需先通过页面点击启用，实际出声受浏览器、系统音量和语音支持影响。
- 刷新会停止旧计时，再次开盒可恢复演示；记录保留。演示每轮最多提醒两次，重新开盒或稍后提醒可开启新一轮。
- 示例计划默认按浏览器当地日期生效，均为虚构药品。所有事件保存在该浏览器 localStorage（最近 300 条），不是医疗记录服务。
- 确认动作针对当前时间的整组药品；部分药品已服用的细粒度记录尚未实现。暂无图片识别、药品实物照片、自动配药或家属远程通知。

## Render 部署

仓库已包含 `render.yaml`，可以使用 Render Blueprint 导入；也可在 Web Service 中连接仓库并配置：

- Runtime：Node；Node.js 22 或以上。
- Build Command：`npm test`。
- Start Command：`npm start`。
- Health Check：`/healthz`。
- 环境变量：`HOST=0.0.0.0`、`DEEPSEEK_MODEL=deepseek-flash`、`DEEPSEEK_API_KEY`（在 Render 中填写）。
- 端口自动读取 Render 的 `PORT`。演示默认使用免费实例，可能出现休眠后的冷启动等待。

服务器仅提供白名单静态文件，不会提供 `.env` 或源码配置文件。密钥只在服务器环境中读取。模型请求最多 3 个并发、每实例每日最多 100 次，可通过 `AI_DAILY_LIMIT` 调整；计数是内存级，重启会重置，不是严格账单上限。公开面试演示只使用虚构用药安排。

本地可复制 `.env.example` 为 `.env` 后填写密钥，已加入 Git 忽略规则。不要把 `.env` 上传或提交。
